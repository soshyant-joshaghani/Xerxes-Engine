## Phase 3 in detail: darius and the tools

Decided 2026-10-06: darius stays the working game for a long stretch. Every game mode of the [taxonomy](../engine/src/modules/flow/game-mode-taxonomy.html) gets a scene in it (21 scenes), each playable **offline**, **online** and **spectated**; the engine grows the tools that games always need and other engines do not ship: a rules runtime, **Warp** (level manager), quests, dialogue, save, text, UI kit, and the Colyseus-style multiplayer server, all built **because a darius scene needs them**. A stage is `done` only when a scene uses it and its tests pass. Stages are taken in the order of the dependency column; the single-player track (3.x) and the multiplayer track (M#) run side by side.

Tools are designed as engine modules from the start (the decision is made: every game needs them), and still proven by a game before `done`. Reference material: a Unity dialogue/quest package kept in `__temp__/` (gitignored, design reference only, see [dialogue-quest.md](../__docs__/dialogue-quest.md)); the room runtime for multiplayer ([backend-multiplayer.md](../__docs__/backend-multiplayer.md)); Rapier for physics ([physics.md](../__docs__/physics.md)).

### The line

**One sequence** for the whole of Phase 3: games, the engine layer each one adds, the editor feature it needs, and the backend (M track) piece it needs. Sorted on 2026-10-14 by dependency first, then by alternating Darius (D, 2D) and Cyrus (C, 3D) where the dependencies allow. Where two games of one track sit together, a layer is the reason: the other track is waiting for it.

Rules of the line:

- **One step, one game (or two small ones) and one layer.** A step is `done` when its game passes the offline matrix. Its online and spectated runs are done at the step named in *Online at* (the M stage they need), so a game is never finished before the backend it needs.
- **Backend is in the line, not after it.** M0 (step 5) needs no game and can start as soon as step 1 is done. M1 starts with the first online game (Qanat, step 9): a turn-based rule set, the cheapest server-authoritative case. Spectating (M3, step 11) comes before the duel matchmaker (M2, step 12), because the solo games need a room to be watched in.
- **Extract on the second use.** Each piece of code moves into the engine or an add-on when the second game needs it (the step says which). Until then it stays in its game ([gdd README](../__docs__/gdd/README.md#the-build-ladder)).
- **Names in this table are the GDD names.** The code uses these names (renames applied 2026-10-14, 2026-10-17 and 2026-10-18: Siavash (was Rakhsh), Arash's Arrow, Ahriman's Horde).
- **Beside the line, not in it:** the editor's own track (2c to 2i, Canvas and UI 2h included where a step needs it), rendering profiles (2e), and progressive web loading (2j) run as their steps require, and Phase 9 (extraction) happens inside the steps above.
- **Proposal from step 13 on.** Steps 1 to 12 are settled by dependency; the rest is the order the dependencies give today and is reviewed as each step lands. A step that shows a missing dependency moves the step after it.
