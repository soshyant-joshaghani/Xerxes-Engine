## Phase 3 in detail: darius and the tools

Decided 2026-10-06: darius stays the working game for a long stretch. Every game mode of the [taxonomy](../engine/src/modules/flow/game-mode-taxonomy.html) gets a scene in it (21 scenes), each playable **offline**, **online** and **spectated**; the engine grows the tools that games always need and other engines do not ship: a rules runtime, **Warp** (level manager), quests, dialogue, save, text, UI kit, and the Colyseus-style multiplayer server, all built **because a darius scene needs them**. A stage is `done` only when a scene uses it and its tests pass. Stages are taken in the order of the dependency column; the single-player track (3.x) and the multiplayer track (M#) run side by side.

Tools are designed as engine modules from the start (the decision is made: every game needs them), and still proven by a game before `done`. Reference material: a Unity dialogue/quest package kept in `__temp__/` (gitignored, design reference only, see [dialogue-quest.md](../__docs__/dialogue-quest.md)); Colyseus for multiplayer ([multiplayer.md](../__docs__/multiplayer.md)); Rapier for physics ([physics.md](../__docs__/physics.md)).
