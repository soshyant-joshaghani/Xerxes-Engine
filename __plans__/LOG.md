- **The code half of stage 2j: measured, and decided against.** The question was whether a web game can download only the scene it plays instead of every scene's logic. Answer, from the build itself: Cyrus ships a **34.57 MB** module (**8.74 MB** gzipped) and **all** of its own code — 21 scenes, three playable games, the rules crate — is **0.15 MB of 32.07 MB, 0.5%**. Bevy is 56.7% (`bevy_ecs` alone 24.6%), the renderer 5.6%, physics 3.6%. A per-scene code package would move about **7 KB**. `dx build --wasm-split` (experimental, splits a linked module behind `#[wasm_split]` functions) is a real tool but the wrong lever here, and nothing in the toolchain shares one Bevy runtime across several wasm modules — separate cdylibs each link their own copy. So: **no scene code packages**, written up with the numbers in [web-progressive.md](../__docs__/web-progressive.md) (status, target, build side, non-goals all say so now).
- **What the measurement bought instead:**
  - **`xerxes-ctrl game|template weigh <name>`** (`__ctrl__/utils/game/weigh.py`, no dependencies: it walks the wasm's sections and its name section): the module and what it costs gzipped, the art bundles, and which crate wrote the code. The decision above is re-checkable at any time, which is the point — if a game's own code ever grows to megabytes, `weigh` is what will say so.
  - **The shipped site compresses properly.** The nginx template a web build gets now sets `gzip_comp_level 6` (plus `gzip_vary`, `gzip_min_length`): 9.87 → 8.74 MB on Cyrus, about **25x what splitting every scene would have saved**.
